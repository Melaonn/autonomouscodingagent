# SDLC harness paired pilot — 2026-09-20

This is a real five-task paired pilot on `Melaonn/sdlc-harness-demo`, starting every checkout at commit `06f21c3d5bf4ab2ea3b7ce45c57710310be65ad1`. Both arms used `gpt-5.6-luna` with low reasoning. Hidden behavior checks lived outside the agent checkouts.

**Verdict: INCONCLUSIVE. No benefit claim is justified by this pilot.**

| Result                       | Manual SDLC prompt |   Harness workflow |
| ---------------------------- | -----------------: | -----------------: |
| Final hidden quality         |                5/5 |                5/5 |
| Quality before native review |                5/5 |                4/5 |
| Measured total tokens        |            790,468 | at least 1,142,019 |
| Measured uncached tokens     |            112,580 |   at least 175,619 |
| Wall time                    |             427.2s |             760.0s |
| Repair iterations            |                  0 |                  2 |

The harness implementation assigned duplicate IDs in the bulk-create task. Configured build, lint, type, test, and dependency gates all passed. Native Codex review independently found the duplicate-ID defect, and a repair turn fixed it before the final hidden check. This demonstrates value from independent review, but the manual baseline produced correct implementations for all five tasks, so overall quality did not improve.

The harness used 1.44× the measured total tokens and 1.56× the measured uncached tokens. These are lower bounds because Codex CLI 0.145.0 reported zero usage for all five native review turns. The evaluator detected those active unmetered turns and refused to make an efficiency claim.

The pilot also exposed and fixed a policy integration defect: the TypeScript profile invoked an aggregate `npm test` script while expecting a Vitest JSON report that the command did not create. The corrected profile invokes local Vitest directly and the gate now produces valid machine-readable evidence.

These were small, explicit API tasks with no company documents configured. That distribution strongly favors the manual baseline and does not test the main company-integration hypothesis. The next evaluation should use blinded historical defects and incident regressions, then compare two separate questions:

1. **Control-plane value:** give both arms identical company context and measure whether enforced gates plus independent review improve escaped-defect rate.
2. **Context-delivery value:** give both arms only the normal developer prompt and measure whether automatic retrieval of architecture, policy, and incident knowledge improves quality and reduces human prompting.

Use at least 10–20 representative tasks before making a company-wide performance claim. Preserve raw JSONL and hidden checks under the ignored evaluation directories with the company’s retention controls.
